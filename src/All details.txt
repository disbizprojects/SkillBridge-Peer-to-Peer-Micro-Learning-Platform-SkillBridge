================================================================================
                           1. PLATFORM OVERVIEW
================================================================================

SkillShare is a comprehensive peer-to-peer learning platform that connects 
learners with mentors for micro-courses and live sessions. The platform uses 
a token-based payment system and includes gamification features.

KEY CAPABILITIES:
- User authentication with role-based access (Learner, Mentor, Both)
- Course creation and management
- Live 1-on-1 and group session booking
- Token-based economy with wallet management
- Gamification (XP, Levels, Badges, Leaderboards)
- Community forum
- Real-time messaging
- Admin dashboard
- Progress tracking
- Review and rating system

================================================================================

================================================================================
                            3. ARCHITECTURE
================================================================================

ARCHITECTURE TYPE:
Three-tier client-server architecture

FLOW:
Frontend (React) → Supabase Edge Function (Hono Server) → KV Store (Database)

API BASE URL:
https://{projectId}.supabase.co/functions/v1/make-server-d45a5820

AUTHENTICATION:
- Bearer token authentication using Supabase public anon key
- Password hashing using SHA-256
- Session management via localStorage
- Admin authentication via separate admin token

DATA STORAGE:
All data is stored in Supabase's Key-Value store with prefixed keys:
- user:{userId}
- auth:{email}
- course:{courseId}
- session:{sessionId}
- enrollment:{userId}:{courseId}
- transaction:{transactionId}
- review:{reviewId}
- notification:{notificationId}
- forumPost:{postId}
- chatSession:{sessionId}
- chatMessage:{messageId}

================================================================================
                          7. DATABASE SCHEMA
================================================================================

All data is stored in Supabase Key-Value store with the following structure:

USER OBJECT:
{
  id: string                    // user-{timestamp}-{random}
  email: string                 // Unique email address
  name: string                  // Display name
  role: string                  // 'learner' | 'mentor' | 'both'
  avatar?: string               // Profile picture URL
  bio?: string                  // User biography
  skills: string[]              // Array of skill tags
  level: number                 // Calculated from XP
  xp: number                    // Experience points
  tokens: number                // Platform currency
  badges: Badge[]               // Array of earned badges
  rating?: number               // Average rating (mentors)
  totalSessions?: number        // Session count (mentors)
  totalEarnings?: number        // Token earnings (mentors)
  createdAt: string            // ISO timestamp
  passwordHash: string          // SHA-256 hashed password
  status?: string              // 'active' | 'suspended'
  suspendedAt?: string         // ISO timestamp
  unsuspendedAt?: string       // ISO timestamp
  roles?: string[]             // Admin roles
}

BADGE OBJECT:
{
  id: string                    // Badge identifier
  name: string                  // Display name
  icon: string                  // Emoji or icon
  description: string           // Badge description
  earnedAt: string             // ISO timestamp
}

COURSE OBJECT:
{
  id: string                    // course-{timestamp}-{random}
  title: string                 // Course name
  description: string           // Course description
  mentorId: string              // Reference to mentor
  mentorName: string            // Mentor display name
  mentorAvatar?: string         // Mentor profile picture
  category: string              // Course category
  price: number                 // Token price
  rating: number                // Average rating
  thumbnail: string             // Cover image URL
  modules: CourseModule[]       // Array of modules
  resources: Resource[]         // Array of resources
  enrolled: number              // Enrollment count
  duration: string              // Total duration
  language: string              // Course language
  createdAt: string            // ISO timestamp
}

COURSE MODULE:
{
  id: string                    // Module identifier
  title: string                 // Module name
  duration: string              // Module duration
  videoUrl?: string             // Video URL
  completed?: boolean           // Completion status
}

RESOURCE:
{
  id: string                    // Resource identifier
  title: string                 // Resource name
  type: string                  // 'pdf' | 'link'
  url: string                   // Resource URL
}

SESSION OBJECT:
{
  id: string                    // session-{timestamp}-{random}
  mentorId: string              // Reference to mentor
  mentorName: string            // Mentor display name
  mentorAvatar?: string         // Mentor profile picture
  learnerId?: string            // Reference to learner
  learnerName?: string          // Learner display name
  type: string                  // '1-on-1' | 'group'
  title: string                 // Session title
  date: string                  // Session date
  startTime: string             // Start time
  endTime: string               // End time
  status: string                // 'upcoming' | 'in-progress' | 'completed' | 'cancelled'
  tokens: number                // Session price
  meetingUrl?: string           // Video conference URL
  createdAt: string            // ISO timestamp
}

TRANSACTION OBJECT:
{
  id: string                    // trans-{timestamp}-{random}
  userId: string                // Reference to user
  date: string                  // ISO timestamp
  description: string           // Transaction description
  amount: number                // Token amount (negative for debit)
  type: string                  // 'credit' | 'debit'
  status: string                // 'completed' | 'pending' | 'failed'
}

ENROLLMENT OBJECT:
{
  userId: string                // Reference to user
  courseId: string              // Reference to course
  enrolledAt: string           // ISO timestamp
  progress: number              // Completion percentage
  completedModules: string[]    // Array of completed module IDs
}

REVIEW OBJECT:
{
  id: string                    // review-{timestamp}-{random}
  courseId?: string             // Reference to course
  mentorId?: string             // Reference to mentor
  userId: string                // Reference to reviewer
  userName: string              // Reviewer display name
  userAvatar?: string           // Reviewer profile picture
  rating: number                // 1-5 star rating
  tags: string[]                // Review tags
  comment: string               // Review text
  date: string                  // ISO timestamp
}

FORUM POST OBJECT:
{
  id: string                    // post-{timestamp}-{random}
  category: string              // Post category
  title: string                 // Post title
  content: string               // Post content
  authorId: string              // Reference to author
  authorName: string            // Author display name
  authorAvatar?: string         // Author profile picture
  replies: number               // Reply count
  lastActive: string           // ISO timestamp
  createdAt: string            // ISO timestamp
}

NOTIFICATION OBJECT:
{
  id: string                    // notif-{timestamp}-{random}
  userId: string                // Reference to user
  type: string                  // 'session' | 'badge' | 'message' | 'system'
  title: string                 // Notification title
  message: string               // Notification message
  timestamp: string            // ISO timestamp
  read: boolean                 // Read status
}

CHAT SESSION OBJECT:
{
  id: string                    // chat-{timestamp}-{random}
  participants: string[]        // Array of user IDs
  participantNames: object      // Map of userId to name
  participantAvatars: object    // Map of userId to avatar
  lastMessage: string           // Last message content
  lastMessageTime: string      // ISO timestamp
  isPaid: boolean               // Payment status
  createdAt: string            // ISO timestamp
}

CHAT MESSAGE OBJECT:
{
  id: string                    // msg-{timestamp}-{random}
  sessionId: string             // Reference to chat session
  senderId: string              // Reference to sender
  senderName: string            // Sender display name
  content: string               // Message content
  timestamp: string            // ISO timestamp
  type: string                  // 'text' | 'system'
}

KEY-VALUE STORE KEYS:
- user:{userId} → User object
- auth:{email} → userId string
- course:{courseId} → Course object
- session:{sessionId} → Session object
- enrollment:{userId}:{courseId} → Enrollment object
- transaction:{transactionId} → Transaction object
- review:{reviewId} → Review object
- notification:{notificationId} → Notification object
- forumPost:{postId} → ForumPost object
- chatSession:{sessionId} → ChatSession object
- chatMessage:{messageId} → ChatMessage object

RELATIONSHIP TRACKING:
- mentorCourses:{mentorId} → string[] (course IDs)
- userEnrollments:{userId} → string[] (course IDs)
- userSessions:{userId} → string[] (session IDs)
- userTransactions:{userId} → string[] (transaction IDs)
- userNotifications:{userId} → string[] (notification IDs)
- courseReviews:{courseId} → string[] (review IDs)
- mentorReviews:{mentorId} → string[] (review IDs)

================================================================================
                           9. USER FLOWS
================================================================================

9.1 NEW USER REGISTRATION FLOW
--------------------------------
1. User visits landing page (/)
2. Clicks "Get Started" or "Sign Up"
3. Navigates to /signup
4. Fills form:
   - Email
   - Password
   - Name
   - Role selection (Learner, Mentor, Both)
5. Submits form
6. Backend creates user with:
   - Initial level: 1
   - Initial XP: 0
   - Initial tokens: 100
   - Early Adopter badge
7. User logged in automatically
8. Redirected to /onboarding
9. Selects skills (optional)
10. Redirected to /dashboard

9.2 COURSE ENROLLMENT FLOW
---------------------------
1. Learner browses /explore
2. Applies filters (category, search)
3. Clicks on course card
4. Navigates to /course/:id
5. Reviews:
   - Course details
   - Modules
   - Reviews
   - Mentor profile
6. Clicks "Enroll Now"
7. System checks:
   - User token balance
   - Not already enrolled
8. Deducts tokens from learner
9. Adds tokens to mentor
10. Creates enrollment record
11. Creates transactions (both parties)
12. Awards 50 XP to learner
13. Sends notifications (both parties)
14. Shows success message
15. Redirects to course player

9.3 COURSE LEARNING FLOW
--------------------------
1. Learner accesses enrolled course
2. Navigates to /course/:id/play
3. Views course modules list
4. Selects first/next incomplete module
5. Watches video
6. Clicks "Mark as Complete"
7. Backend:
   - Updates enrollment progress
   - Awards 20 XP
   - Checks for course completion
8. If course completed:
   - Awards bonus 100 XP
   - Checks for new badges
   - Sends completion notification
9. Learner continues to next module

9.4 SESSION BOOKING FLOW
--------------------------
1. Learner browses mentor profile
2. Views available sessions
3. Clicks "Book Session"
4. Selects:
   - Date
   - Time slot
   - Session type (1-on-1/group)
5. Reviews token cost
6. Confirms booking
7. System:
   - Checks token balance
   - Deducts tokens from learner
   - Creates session record
   - Generates meeting URL
   - Creates transaction
   - Sends notifications (both parties)
8. Session appears in dashboard
9. On session day:
   - Participants join via meeting URL
   - Status updates to "in-progress"
10. After session:
    - Mentor marks as completed
    - Tokens transferred to mentor
    - XP awarded (both parties)
    - Review prompt sent to learner

9.5 COURSE CREATION FLOW (MENTOR)
-----------------------------------
1. Mentor navigates to /create-course
2. Fills course form:
   - Title
   - Description
   - Category
   - Price (tokens)
   - Thumbnail URL
   - Language
3. Adds modules:
   - Module title
   - Duration
   - Video URL
4. Adds resources:
   - Resource title
   - Type (PDF/Link)
   - URL
5. Reviews course preview
6. Clicks "Publish Course"
7. Backend:
   - Creates course record
   - Links to mentor
   - Awards 100 XP
   - Sends confirmation notification
8. Course appears in explore page
9. Course listed in mentor dashboard

9.6 GAMIFICATION FLOW
----------------------
XP Earning:
- Automatic on specific actions
- Real-time level calculation
- Level-up notification if threshold crossed
- New badge check on level-up

Badge Earning:
- Checked after major events:
  * Course completion
  * Session completion
  * Level-up
- New badges appear in profile
- Notification sent for new badge

Leaderboard:
- Updated after XP changes
- Shows top 100 users
- Sorted by XP descending
- Displays level and badges

================================================================================
                         11. TROUBLESHOOTING
================================================================================

COMMON ISSUES:

1. "Failed to fetch" errors
   - Backend server not running (shouldn't happen in production)
   - Check Supabase Edge Function status
   - Verify projectId in /utils/supabase/info.tsx

2. Authentication failures
   - Check email/password correctness
   - Verify user exists in database
   - Clear localStorage and try again

3. Token deduction errors
   - Verify user has sufficient tokens
   - Check transaction history
   - Use wallet top-up feature

4. Course enrollment issues
   - Confirm course exists
   - Check if already enrolled
   - Verify token balance

5. Progress not saving
   - Check enrollment exists
   - Verify moduleId is correct
   - Check console for errors

6. XP not updating
   - XP updates are automatic
   - Check user object in database
   - Verify action triggers XP award

7. Badges not appearing
   - Badges checked after specific events
   - Must meet badge criteria
   - Check badge logic in backend

8. Admin login failing
   - Use correct admin credentials
   - Check admin route exists
   - Verify admin token storage

DEBUGGING:
